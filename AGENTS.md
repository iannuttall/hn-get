# Agent guide for hn-get

This repo is a TypeScript monorepo for one Hacker News data pipeline. It ships a JSON-first CLI and stdio MCP server through npm, plus a Cloudflare Worker that serves the HTTP API, RSS, and remote MCP.

Default CLI and API output is JSON. Keep that contract stable unless the user asks for a breaking change.

## Start here

- Read `README.md` before changing commands, routes, or output.
- Hacker News behavior belongs in `packages/core`.
- CLI wiring and output live in `packages/cli`.
- The shared MCP tool registry lives in `packages/mcp`.
- RSS routing and XML rendering live in `packages/rss`.
- Worker routes and transports live in `apps/worker`.
- Run `pnpm check`, `pnpm pack:dry-run`, and `pnpm worker:deploy:dry-run` before handing work back.

## Local commands

```bash
corepack enable
pnpm install
pnpm dev
pnpm dev:cli -- search sqlite
pnpm types
pnpm build
pnpm typecheck
pnpm test
pnpm lint
pnpm security:check
pnpm pack:dry-run
pnpm worker:deploy:dry-run
```

Use `node packages/cli/dist/cli.js <command>` after a build.

## Project shape

- `packages/core/src/hn.ts` owns Firebase, Algolia, HTML-backed lists, normalization, and request limits.
- `packages/core/src/http.ts` wraps `fetch` with timeouts and conservative retries.
- `packages/mcp/src/index.ts` registers tools once for local stdio and remote HTTP.
- `packages/rss/src/index.ts` maps feed URLs to core calls and renders RSS.
- `packages/cli/src/cli.ts` owns commands, help, options, and argument parsing.
- `packages/cli/src/output.ts` and `markdown.ts` own terminal formats.
- `apps/worker/src/index.ts` owns Hono routes and the raw MCP SDK Streamable HTTP transport.
- `apps/worker/wrangler.jsonc` is the Worker config source of truth.
- Worker binding types are generated by Wrangler. Never hand-edit `worker-configuration.d.ts`.

Core must not import a client package. Clients can depend on core and shared transport-neutral packages.

## Command behavior

- Search and section commands default to newest first with `sort: "date"`.
- Popular views use `--sort points`.
- `item <id>` returns the Firebase item by default.
- `item <id> --comments` fetches a bounded comment tree.
- `item <id> --feed` returns searchable comments for that item.
- `user <username>` returns a compact profile and `submittedCount`.
- `user <username> --submitted-limit <count>` includes submitted item IDs.
- `user <username> --feed` returns user activity.
- `hn-get mcp` runs the local stdio MCP server.

Do not crawl linked article URLs by default. This project fetches Hacker News data. Pulling external articles changes runtime, failure modes, and user expectations.

## Output and route rules

- JSON stays the CLI and HTTP default.
- `compact` must be valid JSON with no extra text.
- `ndjson` prints one JSON object per line.
- Markdown should be readable and stable enough for agents to quote.
- Text output can be human-friendly, with no progress spinners or decoration.
- RSS stays compatible with the documented hnfeed-style paths and parameters.
- The remote MCP endpoint uses Streamable HTTP. Do not add deprecated SSE support.
- Keep MCP tools stateless unless a real feature needs durable per-session state.
- Errors go to stderr in the CLI and use structured JSON in the API.

## Upstream API rules

- Use Firebase for live items, users, and official lists.
- Use Algolia for search, comments, historical lookups, and author feeds.
- Keep request limits bounded.
- Keep retries conservative.
- Do not add auth, cookies, browser state, or hidden local config.

## Dependency rules

Keep the dependency list short.

Defuddle handles Markdown conversion from Hacker News HTML fragments. Do not add Readability, Turndown, JSDOM, or a direct DOM dependency without a tested reason.

The Worker uses the MCP SDK's `WebStandardStreamableHTTPServerTransport` directly. Do not add the full Cloudflare `agents` package unless the product needs Agents or durable MCP state.

## Cloudflare rules

- Use current Wrangler and Workers types.
- Prefer `wrangler.jsonc`.
- Run `pnpm types` after binding changes and commit the generated file.
- Do not commit account IDs, routes, secrets, `.dev.vars`, `.wrangler`, or build output.
- Build and dry-run validation are fine. Do not deploy or attach public routes unless the user asks.
- Create a new MCP server and transport for every remote MCP request.
- Await every promise. Use `ctx.waitUntil()` only for work that should continue after a response.

## Publishing checks

The public npm package is `packages/cli`. It contains the `hn-get` binary, stdio MCP command, public library exports, skill, README, and license.

```bash
pnpm check
pnpm security:check
pnpm pack:dry-run
```

Inspect the tarball list. It should include `dist`, `skills`, `README.md`, `LICENSE`, and `package.json`.

`.github/workflows/publish.yml` publishes only when `packages/cli/package.json` has a version that differs from npm. It uses npm trusted publishing through GitHub OIDC. Do not add an `NPM_TOKEN`.
